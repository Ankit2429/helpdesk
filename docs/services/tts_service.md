# Text-to-Speech (TTS) Service Documentation

This document describes the design, backend abstraction, queue model, playback cancellation/interruption hooks, thread configuration, and diagnostics settings for the `TTSService`.

---

## 1. Architectural Role

The TTS Service converts text answers generated by the inference layer into audible speech:
* **Synthesis & Playback**: It consumes `ANSWER_READY` events and produces `TTS_STARTED`, `TTS_COMPLETED`, and `TTS_INTERRUPTED` events.
* **Decoupled**: It does NOT interact with the RobotStateMachine or the InteractionManager directly. It only acts as an audio rendering sink.

---

## 2. Decoupled Speech Backend Abstraction

The service utilizes the `BaseSpeechBackend` interface to synthesize text and play audio:
```python
class BaseSpeechBackend(ABC):
    @abstractmethod
    def load_model(self) -> float:
        pass

    @abstractmethod
    def synthesize_and_play(self, text: str, stop_event: threading.Event, on_start_callback: Any) -> float:
        pass

    @abstractmethod
    def cancel(self) -> None:
        pass
```
* **`PiperBackend`**: Bridges to the local Piper engine, allowing config parameters such as speed, voice model, volume, and sound device outputs.
* **`MockSpeechBackend`**: Generates simulated synthesis delay and word-length playback delays for headless validation during CI/CD test runs.

---

## 3. FIFO Worker Thread & Interruption Model

* **Worker Loop**: A background daemon worker thread (`tts_service-worker`) processes text synthesis requests sequentially.
* **Preemption/Interruption**: When a new `ANSWER_READY` event is published, or when a user interrupts the robot, the system calls `interrupt()`:
  1. Sets the internal `_preempt_event` flag.
  2. Invokes `cancel()` on the active backend to abort audio output.
  3. Publishes `TTS_INTERRUPTED` showing the exact duration (in milliseconds) the robot spoke before interruption.
  4. Immediately starts synthesizing the new answer from the queue.

---

## 4. Diagnostics & Status Reporting

The service tracks diagnostic metrics including:
* **`playback_latency`**: Speaking duration.
* **`synthesis_latency`**: Overhead of generating the audio file or warming up the playback streams.
* **`failures`**: Unhandled audio driver or synthesis exceptions.
